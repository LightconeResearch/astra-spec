# v0.1 schema: what changed, and why

This compares `main` (`1bc6eb8`) with the branch `v0.1-schema`.

The "Why" column gives the reason and where it comes from:

- an RFC (0003–0007) or the draft tidy-up RFC
- a decision of the design, D1–D12 (`2026-11-03-v0.1-schema-design.md` §2)
- a ruling made during implementation, R1–R25 (in the design's text)

## Package and build

| | Before | Now | Why |
|---|---|---|---|
| What ships | The LinkML YAML plus two generated Python models (dataclasses and pydantic), with a dependency on `linkml-runtime` | The LinkML sources, the generated JSON Schemas and the record's JSON-LD context. No Python and no dependencies | D7: nothing in the package can disagree with the contract. The pydantic models enforced neither rules nor key checks, and needed their ids injected |
| Python | ≥ 3.9 | ≥ 3.10 | `importlib.resources` reads namespace packages only from 3.10 (tested). 3.9 is end-of-life |
| Recipes | `gen-python`, `gen-project` (Java, TypeScript, OWL…), and an examples test that was allowed to fail | `gen-schema`; `check-generated`, `pytest` and lint inside `just test` | One artefact, drift-checked. The dead generators are gone |
| CI | Python 3.9–3.13, plus a job checking the Python models | Python 3.10–3.13; `just test` runs the drift check, with tags fetched | R8: one drift check, not two |
| Release | Regenerated the Python models | Regenerates the contract with the release version; `git push --atomic` | The contract is the thing that's versioned |

## The contract

| | Before | Now | Why |
|---|---|---|---|
| What defines validity | Unclear: LinkML, two Python models, and a stock JSON Schema built only for the docs and never tested | The committed, generated JSON Schema | D1: language-neutral (astra-tools, typescript-astra, editors). It is what LinkML's own validator uses |
| Did it work? | No. `main`'s published JSON Schema rejected `main`'s own valid fixture and the iris example: a rule turned `options` into an array check | Every fixture and example validates. Ajv (JavaScript) agrees with Python's `jsonschema` on all 108 fixtures | The tests now check the artefact consumers use |
| Map keys | Not checked: `Not-A-Valid-Id!` passed as a decision id | Checked through `propertyNames`, added by the generator extension | D3: stock LinkML can't constrain map keys |
| Map values | Also accepted the shorthand `seed_42: "42"` and `seed_42:` (null) | One written form per entry, and the key isn't repeated inside it | D3: one way to write a file |
| `null` | Accepted for any optional field | Rejected | D12 |
| Duplicate list entries | Accepted (`inputs: [a, a]`) | Rejected (`uniqueItems`) | R21 |
| Unused definitions | Kept, including id-bearing shapes that contradict the map form | Pruned to what the root reaches | R23: type generators would emit both shapes |
| Top-level keywords | Included LinkML's `metamodel_version` | Standard JSON Schema only; the version is in `$comment` | R20: strict validators (Ajv) refused to compile the schema |
| Schema ids | One `$id` per model | One per file, so the closed and open record schemas are distinct | R15: distinct resources need distinct ids |

## Names, ids and patterns

| | Before | Now | Why |
|---|---|---|---|
| Kind of id | LinkML `identifier`: globally unique, so in RDF two options called `none` merged into one node | `key`: unique within its map. The only `identifier` is the environment IRI | D4: author-given ids are local names; names given by the world are identifiers |
| Id grammar | Written out 8 times, with a reserved-word list. Universe ids allowed `-` | Written once, in `types.yaml`; one grammar everywhere | D5: after RFC 0004, an id's kind comes from the field it's in, so category words can't clash |
| Named types | None | `id`, `address`, `reference`, `option_reference`, `condition`, `commit_id`, `content_hash`, `spec_version`, `timestamp` | The RFCs' grammars, defined once and used by name (D11) |
| Patterns | Used `\d`, `.` and a bare `$` | Explicit character classes, ending in `$(?!\n)` | R5, R7: Python and ECMA-262 read `.`, `\s`, `\d` and `$` differently; the contract must mean the same in both |

## The analysis document

| | Before | Now | Why |
|---|---|---|---|
| Collections | Mixed: inputs and outputs were lists, while decisions, options and insights were maps | Everything referenced by id is a map keyed by id | D2: uniqueness is structural, and the id is written once |
| Analysis | `id` (required in the schema, optional in the spec), `name`, `version`, `path`, inline sub-analyses | `spec_version` (required), optional `label`; outputs required and non-empty | RFC 0004; tidy-up; D6 (nothing referenced `id`) |
| Sub-analyses | Inline or by `path`, wired with `from:` (`../x`, re-exports) and 15 aliasing rules | Declarations, `{path}` or `{url, commit}`; elements read by address (`stage.features`) | RFC 0004, RFC 0007 |
| Declarations | None | `path` or `url` (one of them), a full commit id, and a `url` that must be a remote URL | RFC 0007; R9 |
| Inputs | `type` (data or analysis), `source` (a path, a loader or a URI), `ref`, `use_outputs`, `from` | `path` only: a committed file, relative, without `..` | RFC 0006: a runner has to know what to read. External data comes in through an output |
| Outputs | `format` only recommended; `from` re-exports; inputs were plain ids | `format` required; inputs are references with pins (`x#u`) and addresses; `when` uses a typed grammar | RFC 0003, RFC 0004; `format` was scheduled to become required at 0.1 |
| Decisions | `default`, `from`, a required `label` | No `default` or `from`; `label` optional; options required | RFC 0003 (no universe is privileged); tidy-up |
| Options | `label` required; `excluded: true` plus a separate `excluded_reason` | `label` optional, `tags`; `excluded` is the reason itself and can't be blank; constraints are typed | Tidy-up: one field can't disagree with itself |
| Universes | Separate files in `universes/`, nested selections and presets, no label | In the file; `derived_from` diffs; flat keys for driven analyses; `label`, `tags`; compact `decision: option` | RFC 0003, RFC 0004 |
| Removed classes | `KeyValuePair`, `InputType`, `UniverseNode`, `InsightCollection` | Gone | Unused, or replaced |

## Insights and evidence

| | Before | Now | Why |
|---|---|---|---|
| Insight | `created_at` (required), `derived`, `notes` | None of those; `notes` becomes `description` | Tidy-up: fields nothing read; one name for free prose |
| Evidence | `id`, `snapshot`, `source_commit`; "exactly one of `doi`/`artifact`" stated only in prose | No id, snapshot or commit; exactly one source, enforced; `version` only with a `doi` | Tidy-up; the rule is pushed into the schema |
| Page locator | Both `value` and `page` | W3C's `value` only, with the W3C mappings (`oa:exact`, `rdf:value`, …) | Tidy-up (FragmentSelector swap); R10 |

## The provenance record (new)

| | Before | Now | Why |
|---|---|---|---|
| Records | None | A record schema: content hash, size, commit, inputs (one per entry), environment IRI, runner, times. Closed, with an open variant for checkers reading newer records, and mapped onto PROV-O | RFC 0005; D10; R11 (times are `xsd:dateTime`); R14 |

## Validation rules

| | Before | Now | Why |
|---|---|---|---|
| Where rules lived | Scattered: schema rules, prose in the RFCs, and astra-tools' own codes | One catalogue of 65 codes in five layers (parse, schema, validator, check, runner), each with a level and a source | D9: every tool reports the same codes; ready for the conformance suite |
| What this repository enforces | Little, and incorrectly | Every parse and schema rule, each covered by fixtures | Validation pushed as high as it can go |

## Tests

| | Before | Now | Why |
|---|---|---|---|
| Method | Valid fixtures loaded through the dataclasses, invalid ones through JSON Schema; PyYAML (YAML 1.1) | Every fixture through plain `jsonschema` against the committed contract; YAML 1.2, core schema only | One path, the one consumers use. YAML 1.1 turns `no:` into `False` and keeps duplicate keys silently |
| Fixtures | 12 (3 valid, 9 invalid), checked for "some error somewhere" | 108 (9 valid, 99 invalid). Each invalid one names its rule and location, and fails only there, with the keyword the rule implies | R19, R24 |
| Other tests | None | Generator, types, contract shape, wheel contents, catalogue against fixtures, spec examples, examples; 304 tests in all | Guards so the contract can't loosen quietly |

## Examples, specification and CLAUDE.md

| | Before | Now | Why |
|---|---|---|---|
| Examples | `universes/` files, defaults, an input naming an analysis that doesn't exist, inline sub-analyses | Universes in the file, data loaded by an output built once, a pinned comparison; `iris_pipeline` as three driven analyses | RFCs 0003, 0004, 0006; correct for a reader |
| Specification | "The ASTRA Specification Explained": a tutorial with hand-written field tables that disagreed with the schema | Normative text: RFC 2119 keywords, ABNF grammar, the rule catalogue, and links to the generated field reference | D8: each field is defined once, in LinkML |
| CLAUDE.md | Said to run `gen-python` and listed the Python models | Describes the modules, the contract, the tests and the release flow | Tom asked |
